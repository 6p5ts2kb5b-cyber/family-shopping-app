# 子ども用タブレットの QR 登録（設計・Phase 1）
更新: 2026-10-15 ／ ブランチ kids-messages-implementation ／ main・本番 Firebase は未変更

6桁番号方式（KIDS_MESSAGES_REVIEW.md §3）は廃止し、この QR 方式を現行仕様とする。

## 1. 結論：Spark（無料）プランで実現できる
- 使うもの：Firebase Authentication の**匿名ログイン**（Spark で無料。Identity Platform へのアップグレードはしない）、Firestore、Firestore セキュリティルール、GitHub Pages
- 使わないもの：Cloud Functions、App Check の有料機能、外部の QR サービス
- 「サーバー側の検証」はすべて **Firestore セキュリティルール**で行う（ルールは Google のサーバーで実行されるため、画面を改造しても回避できない）
- 1回きり・期限つき・管理者のみ・同時に1回だけ、をルールで強制できることを、エミュレーターのテストで確認する（§5）

## 2. 流れ
```
タブレット（kids.html）                       管理者のスマホ（app.html, Googleログイン済み）
1. 匿名ログイン（画面操作なし）→ uid
2. ランダムな登録トークン T（128bit）を作る
3. kidPairRequests/{uid} に
   { tokenHash: SHA-256(T), createdAt: サーバー時刻 } を保存
4. QR を表示：
   https://…/app.html#pair=<uid>.<T>
   （# の後ろはサイトのサーバーに送られない）
   と「確認の絵」3つ（uid と T から計算）
                                               5. 標準カメラで QR を読む → app.html が開く
                                                  （未ログインならログイン後に続きへ）
                                               6. 確認画面：
                                                 タブレットに出ている「確認の絵」を4つの中から選ぶ（違えば登録しない）／端末名を入力
                                               7. 「このタブレットを登録」を押す（明示的な承認）
                                               8. 1回のまとめ書き込み（batch）：
                                                  ・kidDevices/{uid} を作成（pairToken: T）
                                                  ・kidPairRequests/{uid} を削除
9. 自分の kidDevices/{uid} が作られたのを見て
   伝言画面に切り替わる（登録結果を端末自身で確認）
10. QR は 5 分ごとに作り直し（10 分で失効）。申請の書き直しはルールで 4 分に1回まで。4 分以内の再読み込みでは同じ QR を出す
```
次回以降：タブレットの匿名ログインは端末に保存されるので、ホーム画面のアイコンから開くだけ。

## 3. ルールで強制すること
| 条件 | 方法 |
|---|---|
| 管理者以外は登録できない | `kidDevices` の作成は `owner()` のみ（名簿の配偶者も不可） |
| QR を読むだけでは登録されない | 登録は管理者が「登録」を押したときの書き込みだけ。QR を読んだ時点では何も書かない |
| 短時間で失効 | 作成時に `request.time < 申請.createdAt + 10分` を確認。`createdAt` はサーバー時刻を強制 |
| 使い回し防止（1回きり） | 登録の書き込みと同時に申請を削除することを要求（`!existsAfter(申請)`）。申請が無ければ作成できない |
| トークンの照合 | `hashing.sha256(pairToken)` が申請の `tokenHash` と一致すること。トークン本体は申請に保存しない |
| 二重承認の防止 | `kidDevices` は作成のみ（既にある端末の上書き不可）。端末名の変更は別ルールで名前だけ |
| 申請の横取り・なりすまし防止 | 申請の文書 ID＝自分の匿名 uid のときだけ作成可。他人の申請は読めない・書けない・消せない |
| 匿名ログインだけでは何も読めない | 伝言・設定の読み取りは `family()` または「`kidDevices/{自分のuid}` が存在する匿名ユーザー」だけ |
| 解除後は読めない | 管理者が `kidDevices/{uid}` を削除 → 次の読み取りから拒否 |
| 買い物・予定・名簿は読めない | 既存ルールは変更しない。匿名ユーザーは `owner()`（uid が違う）も `member()`（メールが無い）も満たさない |

## 4. 脅威と対策
| 脅威 | 対策 |
|---|---|
| QR を写真に撮られた | 中身は匿名 uid と使い捨てトークンだけ。登録できるのは管理者のみで、10 分で失効、使えば消える。長期の秘密は入っていない |
| 他人の QR とすり替える／チャットでリンクを送って管理者に押させる | 確認の絵は uid とトークンから計算（絵はQRの内容から再現可能であり、独立した本人認証や遠隔なりすまし防止の保証にはならない）。管理者は「同じ？」に答えるのではなく、目の前のタブレットに出ている絵を4つの中から選ぶ。登録画面に「タブレットが目の前にあるときだけ／チャットで届いたリンクでは登録しない」と表示。家族タブに「新しく登録」と日時を表示し、すぐ解除できる。※管理者が見ずに登録してしまう操作ミスは完全には防げない（残るリスク） |
| 推測による突破 | トークンは 128bit の乱数。URL・uid だけでは何もできない |
| 申請を大量に作る（荒らし・無料枠の消費） | 申請は自分の uid の1件だけ、書き直しは 4 分に1回まで、削除は管理者だけ（削除→作り直しの抜け道なし）。新しい匿名 uid の大量作成は Firebase 側の制限（同じ IP からの1時間あたりの作成数）で抑えられる。管理者の画面は申請の一覧を表示しない。さらに強くするなら App Check（reCAPTCHA v3、無料）を検討 |
| 管理者以外の家族が登録 | ルールで拒否（配偶者の画面にも登録ボタンを出さないが、それだけに頼らない） |
| 同じサイトの親のログインを奪う | kids.html は名前付き Firebase アプリ（`'kids'`）で初期化し、ログイン状態・端末保存を app.html と分ける |
| タブレットのデータ消去 | 匿名 uid が変わり未登録に戻るだけ（もう一度 QR 登録）。古い登録は管理者が解除 |

## 5. エミュレーターで確認するテスト（tests/rules.test.mjs に追加）
- 未登録の匿名：伝言・設定・子どもの名前を読めない
- 登録済みの匿名：伝言・設定・子どもの名前を読める／書けない
- 匿名（登録済みも含む）：買い物・よく買うもの・予定・名簿・親の名前・定型文を読めない・書けない
- 申請：自分の uid だけ作れる／他人の申請を作れない・読めない・消せない／形式違い・端末時刻の createdAt は拒否
- 登録：管理者のみ成功／配偶者・匿名・名簿外は拒否／トークン違い・期限切れ・申請の削除なし・申請なしは拒否／2回目（二重承認）は拒否／削除後の同じトークンでの再登録は拒否
- 解除：管理者のみ。解除後は伝言を読めない
- 伝言・定型文・設定：不正な形式（121 文字、child4、空の対象、重複、onDate の形式、端末時刻）を拒否
- 既存のルールテストがすべて通る

## 6. 子どもの表示名を Firebase へ移す計画
現在 `lib/schedule-views.js` などに 家族の実名（漢字1文字ずつ）が書かれている（公開リポジトリ）。

1. **このブランチ**：表示名を `familySettings/children`（子ども3人：家族と登録済みタブレットが読める）と `familySettings/parents`（夫・妻：家族だけ）から読む。コードの既定値は「夫・妻・子ども1〜3」の一般名にし、実名をコードから外す。テストのデータもテスト用の名前に置き換える
2. 家族タブに「表示名」の設定を追加（家族が変更できる）
3. **本番への反映順**（ユーザーの承認後）：
   ① ルールを貼り替える → ② 本番の app.html（現行版）は実名のまま動き続ける → ③ このブランチを main に反映 → ④ 家族タブの「家族の呼び名」で5人の名前を入力（1回）
   ③〜④の間だけ「夫・妻・子ども1」と表示される（データは壊れない。予定の保存値は child1〜3 のままで変わらない）
4. 予定の文章入力（「（子どもの名前） サッカー」など）は、設定した表示名で読み取るように変更する
5. 注意：Git の履歴には実名が残る。履歴から消すには履歴の書き換え（強制 push）が必要で、ChatGPT と並行作業中のため、行う場合は別途判断する

## 7. 朝／夕方の切り替え時刻
- **初期値：12:00（正午）より前は「あさ」、12:00 以降は「ゆうがた」**
- 理由：登校前（6〜8 時）と帰宅後（15〜19 時）の間に必ず切り替わり、どちらの時間帯にも余裕がある。学校が早く終わる日や、親が昼に夕方の伝言を入れた場合も自然に表示される。日付が変わると「あさ」に戻る
- 変更：伝言タブの設定で家族が変更できる（`kidSettings/board.eveningFrom`、例 "15:00"）。タブレットでは手動でも切り替えられ、次の切り替え時刻に自動へ戻る

## 9. 既知の小さなリスク（受け入れ）
- 登録に使ったトークンは `kidDevices` に残る（ルールがハッシュ照合に本体を必要とするため）。申請は消えているので再利用はできない。読めるのは家族とその端末だけ
- QR で開いた URL（#pair=…）は、ブラウザ全体の履歴に残ることがある。10 分で失効・1 回きりなので実害はない。開いた直後にアドレス欄からは消す
- 解除されたタブレットは、端末内の伝言・名前の保存（キャッシュ）と「できた！」の記録を消してから登録画面に戻る
- 実機（iPad・Android タブレット・iPhone の標準カメラ）での QR 読み取りは未確認

## 10. ChatGPT再レビューによる追加制限（2026-10-15）
- タブレットは起動時およびFirestore登録監視がキャッシュ由来になった場合、**サーバーで登録済みであると確認するまで伝言画面を表示しない**。接続不能時は登録確認待ちを出す。これは「オフラインでも前回の伝言を表示」という従来案より安全優先であり、オフライン閲覧はv1非対応。
- 端末解除時はローカルの「できた」記録とFirestore永続キャッシュの削除を試みる。消去が失敗しても次回起動時はサーバー確認なしに伝言を表示しない。ただし、第三者が既に撮影・保存した伝言や、ブラウザの物理保存データを遠隔で確実に消すことはできない。
- 3つの確認絵はQRのuidとトークンから計算されるため、第三者にも生成できる。**管理者は目の前の本物のタブレット画面と直接比較すること**。チャットで届いたQRや画面写真から承認しない。4択の正解を押すだけで端末の本人性が保証されるわけではない。
- QRの写真撮影・貼り替え・遠隔送信、絵の衝突を使うなりすましについて、管理者の目視・対面確認が最後の防御である。絵は認証の代替にならない。
- 実機iPad/Android、SafariのQR読み取り、オフライン・復帰・解除・キャッシュ削除失敗は引き続き未検証。本番切替は実機で確認した後に行う。
