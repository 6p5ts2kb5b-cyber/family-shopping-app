# 子どもへの伝言板 v1 設計書（レビュー用・未実装）
更新: 2026-10-15 / 正式版 main は変更しない

## 目的・利用端末
親のスマホで伝言を作成・更新。家庭内タブレットに子ども3名の伝言を1画面で表示。朝/夕方切替。子どもは「できた！」を押す。チェック完了情報はタブレットのローカル保存だけで、親のスマホやFirestoreに送信しない。

## 確定機能
- child1〜child3、朝・夕方、日付別の表示。表示名は認可された利用者だけが読めるFirebaseの家族設定から取得し、公開コードに直書きしない。
- 伝言のテンプレートを親が自由に登録・編集・削除でき、再利用。対象は各子1人または3人全員。
- 繰り返し = 毎日/平日のみ/今日だけ/明日だけ（後二者は指定日の単発）。祝日や休みは手動のお休みモードで停止。
- 一時的な伝言を今日だけ作れる。
- 完了ボタンは端末内の `localStorage`（日付+子ID+朝夕+伝言ID+更新版）だけで保持。翌日になるとその日のチェックは全件初期状態。チェック履歴をサーバーに送らない。プライベートブラウズや保存領域の削除で失われることを明記。
- リアルタイムに同期するのは伝言本文やテンプレート由来の配信だけ。テンプレート自体の変更と配信の関係、過去日の編集仕様は実装前に明確化。
- デフォルトの子ども向け画面は伝言のみ。買い物・夫婦の予定・名簿や管理者リンクを出さない。

## 想定構成
- 親画面は本体 `app.html` の「伝言」タブに追加。タブレット登録・解除は「家族」タブの管理者専用画面。
- タブレット用 `kids.html` は閲覧+端末内チェックだけ。名前付きFirebaseアプリ `initializeApp(firebaseConfig, 'kids')` で親のログイン状態と分離する。Googleログイン画面や6桁番号入力は設けない。
- Firestore `kidNotices`：各伝言 doc は `targets` (child1〜child3 の配列), `period` ('morning'|'evening'), `repeat` ('daily'|'weekdays'|'once'), `onDate` (once のとき YYYY-MM-DD), `text` (1-120文字), `active` (bool), `updatedAt` 等を検討。
- `kidTemplates` は親のみ読み書き（配信データとの区分）。
- 完了チェック専用のFirestoreコレクションは作らない。

## 重要：認証・権限設計（必須）
- 家のタブレットに親のGoogle管理者アカウントをログインさせない。秘密のURLや単純PINだけで無認証のFirestore読み込みを許可しない。
- タブレットではFirebase匿名認証をバックグラウンドで実行（Googleアカウント・ログイン操作なし）。最初の1回だけタブレットに短命のQRコードを表示し、管理者がログイン済みスマホで読み取り承認する。許可した匿名uidだけを `kidDevices/<uid>` に登録。端末紛失時は親が解除。
- Firestoreルールで `kidNotices` の読取を親の既存 `family()` または登録済み端末の匿名uidに限定。書込は親の既存 `family()` のみ。 `kidTemplates` は親のみ許可。`kidDevices` は管理者のみ書込、登録済み端末も自身のレコード以外は読めない。
- 匿名端末に `shoppingItems`, `shoppingFavorites`, `familyMembers`, `familySchedules` の権限を絶対に与えない。
- Firebase Authの匿名ログイン有効化は所有者のFirebase Consoleでの操作が必要か検証すること。ユーザーによる許可の実操作前に本番ルールを書き換えない。
- 匿名UIDがブラウザデータ削除等で変わると再承認が必要。UIDの公開リポジトリ記録禁止。
- `kidDevices` への登録UIで本人確認の方法を検討し、見知らぬUIDを誤登録しない案内を設ける。

## テスト
1. 3人分が同時表示、朝/夕方切替、土日には平日限定が出ない。
2. 毎日・平日・1回、対象1名/全員、日付を跨いだ自動チェック切替。
3. 親の伝言更新はタブレットに反映。完了チェックは親に反映せず、Firestoreに書き込まれない。
4. 未承認匿名・許可済み匿名・管理者・名簿配偶者・未ログインの権限、買い物予定への匿名アクセス拒否をエミュレーターで検証。
5. iPad/Androidタブレット縦横、iPhone小画面、PC。低速回線・端末保存不可の状態を確認。
6. 旧買い物と予定が残ること、既存ルール回帰テスト。
7. 本番反映前にテスト専用ブランチ→テスト→レビュー→段階的公開。

## 保留事項
- 伝言の定型文を選ぶとそのまま繰り返し配信するか、テンプレートから単発追加するか。
- 祖父母等の追加許可はv1で行わない。
- 完了チェックはタブレット1台のみ（他端末と同期しない）。
- 親画面の公開位置と子ども用端末登録の操作導線。

## 2026-10-15 合意：QRによる初回登録（6桁コード方式は廃止）
- ユーザーが「6桁番号なし」「Googleアカウントでログインなし」「QR方式OK」を明示。**タブレットでGoogleログインせず、初回のみ親がスマホでQRを読み取って承認**する。日常起動では操作不要。
- QRには固定端末ID・認証済み資格情報・長期アクセスキーを入れない。匿名uidとサーバーで検証できるランダムな使い捨て登録トークン、期限等に紐づく短命のペアリング情報を含む。第三者がQRを見ても即座に伝言を閲覧できない。必要に応じ登録トークンは平文で保存しない。
- 親がGoogleログイン済み管理画面でQRを読み取った後、端末名と登録先を確認し、**明示的に承認**。未承認・期限切れ・使用済み・解除済み端末は一切伝言を読めない。QRは例えば10分で期限切れとし更新可能とする。
- **重要**：QRに入ったUID・トークンを単にFirestoreで検索して登録する設計では、管理者の照合前に第三者が申請を横取り・偽装する可能性がある。短命トークンの照合、再使用防止、原子的な登録処理、申請の権限・レート制限、端末自身での登録結果確認をセキュリティルールとテストで検証する。クライアント側だけで安全性を断言しない。
- QR読み取りは親スマホのカメラ利用許可が必要な場合がある。カメラ不可の場合は親スマホ標準カメラ→管理画面へのリンクを使う代替導線を検討（6桁番号は使わない）。
- 無料Spark上のFirestore+匿名認証だけで安全なワンタイム承認を実現できるか**実装・ルール・エミュレータの検証前に保証しない**。必要なサーバー側検証を無料枠内で構築できない場合は代替方式を提案してユーザーの再承認を得る。本番ルールは変更しない。
- QR方式へ移行するため `docs/KIDS_MESSAGES_REVIEW.md` の6桁登録案は**過去のレビュー記録**であり現行仕様ではない。
