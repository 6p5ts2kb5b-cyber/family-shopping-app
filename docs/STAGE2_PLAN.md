## 1. かんたん予定入力：解析仕様

実装：`lib/quick-schedule.js`（端末内だけで動く文章解析。外部AI・有料APIは使わない）
テスト：`tests/quick-schedule.test.mjs`（35件、`node --test tests/quick-schedule.test.mjs`）

### 1-1. 前処理
- 全角→半角（NFKC）。`１１／３`、`６：００`、`～` なども読める。
- 長音「ー」は記号扱いしない（「ボーリング」が壊れない）。

### 1-2. 日付（最初に見つかった1つ）
| 書き方 | 例 | 結果 |
|---|---|---|
| 年月日 | `2026/12/24`、`2026.12.24`、`2026年12月24日` | そのまま |
| 月日（漢字） | `11月3日`、`11月3日(火)` | 年は今年。曜日表記は読み飛ばす |
| 月日（記号） | `11/3`、`11.3` | 年は今年。`6:00`・`6時` とは区別 |
| 相対 | `今日` `明日` `あした` `明後日` `あさって` | 今日を基準に計算 |

- **年を省略して過去の日付になった場合**：日付は変えずに「確認」を出し、来年の候補を示す（例：今日が10/12で `4/1` → 「2026年4月1日は過ぎています。2027年4月1日にしますか？」［来年にする］［このまま］）。
- 年を書いた過去の日付も確認を出す（来年候補はなし）。
- `2/30` などありえない日付は読まない（空欄＋警告）。
- 日付が書かれていなければ **空欄**（今日と決めつけない）。
- 未対応（空欄になる）：`来週土曜`、`土曜日`、`11/3〜11/4` の複数日。→ 段階3以降で検討。

### 1-3. 時刻
- 読める形：`6:00`、`6時`、`6時30分`、`10時半`、`午後2時`、`PM3:00`。
- 2つあれば **1つ目＝出発、2つ目＝帰宅予定**（区切りは `から` `〜` `~` `-` どれでも可）。
- 1つだけのとき：直後に `まで` がある・直前に `帰宅` `帰り` がある → 帰宅予定。それ以外 → 出発。
- 保存形式は `HH:MM`（2桁）＝Firestoreルールと同じ。
- `24:00` など不正な時刻は読まない（空欄＋警告）。
- 帰宅が出発より前（夜勤など）は **入れ替えずに警告** だけ出す。
- 時刻は空欄でも保存できる（今の予定画面と同じく「未定」扱い）。

### 1-4. 誰の予定
- 区切られた単語のときだけ読む：`夫` `パパ` `お父さん` `旦那` `主人`／`妻` `ママ` `お母さん` `嫁` `奥さん`／`家族` `みんな` `全員`
- `夫の実家`、`みんなで動物園` のように語の一部なら **読まない**（予定内容に残す）。
- 夫と妻が両方あれば決めずに警告。
- 読めなければ **未選択**。確認画面で［夫］［妻］［家族］をタップして選ぶ（保存は選ぶまで押せない）。

### 1-5. 予定内容
- 日付・時刻・誰・`から` `まで` `出発` `帰宅` などを取り除いた残り。80文字まで（ルールと同じ）。
- 空なら空欄（手入力）。

### 1-6. 解析結果の形
```js
{ date, name, who, departure, returnTime,   // 読めた値（読めなければ ''）
  missing: ['who', ...],                     // 読めなかった項目
  needsConfirm: [{type:'past-date', date, nextYearDate}],
  warnings: [{type:'invalid-date'|'invalid-time'|'return-before-departure'|'multiple-who'|'extra-times'|'name-too-long'}] }
```
保存できる条件：`date` と `name` があり、`who` が 夫・妻・家族 のどれか（`readyToSave()`）。

## 2. かんたん予定入力：画面の流れ

1. 「今日」画面の予定欄の［＋ 予定を追加］、または「予定」タブの［＋予定］
2. **入力シート**：1行の入力欄「例：11/3 野球大会 6:00〜17:00」＋［読み取る］
   - 入力しながら下に読み取り結果をリアルタイム表示（押さなくても分かる）
3. **確認シート**（その場で直せる）
   - 日付（日付ピッカー）／予定内容（文字）／出発・帰宅予定（時刻ピッカー）／誰の予定［夫］［妻］［家族］
   - 読めなかった欄は橙色の枠＋「読み取れませんでした」
   - 過去の日付は確認の帯［来年にする］［このまま］
   - 警告（帰宅が出発より前など）は一言で表示
   - ［保存］は1回のタップで保存。日付・内容・誰がそろうまで押せない
4. 保存すると `familySchedules` に今と同じ5項目で書き込み → 夫婦の両端末に自動反映（今の仕組みのまま。ルール変更なし）

## 3. 段階2の実装範囲

| 項目 | 内容 |
|---|---|
| 新ホーム（今日タブ） | 今日の予定（夫・妻・家族／内容／出発／帰宅）＋買うもの＋よく買うもの＋下部の追加欄 |
| 3タブ | 今日／予定／家族（家族タブ＝名簿・ログアウト・接続チェックへのリンク） |
| 買い物 | 大きな丸で購入済み、リスト上で＋/−、商品名タップで編集シート（名前・個数・削除）、左スワイプ削除、削除後「元に戻す」（5秒） |
| 追加シート | 商品名・個数・「よく買うものにも登録」、よく買うもの1タップ追加 |
| かんたん予定入力 | 上記1・2 |
| 予定タブ（段階2では最小） | 今日・明日の一覧と編集（週間・帯グラフは段階3） |
| デザイン | 確定済みデザインルール（色・文字・角丸・44px以上） |
| 対象外 | オフライン同期（段階4）、週間表示・帯グラフ（段階3） |

### データとルール
- データの形は **今と同じ**（`shoppingItems` `shoppingFavorites` `familySchedules` `familyMembers`）。移し替え・削除なし。
- 「元に戻す」は削除前のデータを画面内に一時保存し、取り消し時に同じIDで書き戻す（ルールの範囲内）。
- 名前の変更は「新しいIDで作成→古いIDを削除」をトランザクションで行う（IDは商品名から決まるため）。
- 予定の旧 `me` は引き続き「夫」と表示し、書き換えない。
- **Firestoreルールの変更は不要**（段階1で公開したルールのまま動く）。

### ファイル構成（案）
- `app.html`（新UI本体）＋ `lib/quick-schedule.js`（解析）＋ `lib/`（共通処理）
- 今の `shared.html` `schedule.html` は段階2の確認が終わるまで残す（並行運用）。
- 切り替え時：`shared.html` を `app.html` への案内に変更。ブックマークはそのまま使える。

## 4. 進め方と公開の手順

1. **段階1の完了確認**（ユーザー）：ルール公開 → 2人とも check.html で OK → 2台で共有チェックリスト
2. このブランチで段階2を実装（main には入れない）
3. 自動テスト：解析35件＋ルール10件＋画面の模擬テスト（2画面同期・編集シート・元に戻す・かんたん入力）
4. 段階1完了後に `main` へ `app.html` を **追加だけ**（既存ページは変更しない）→ 2台で実機確認
5. 問題なければ `shared.html` を新画面へ切り替え
6. ChatGPTとの衝突回避：作業前に必ず `main` の最新を確認し、変更点を報告してから反映
